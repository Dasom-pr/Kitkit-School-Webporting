## 테스트별 검증 내용

### gameRouteMap.test.ts
- 포팅 완료 게임 → `?level=N` 쿼리 파라미터 반환
- Video 게임 → `/video/{param}` 반환
- Book 게임 → `/book/{param}` 반환
- 미포팅 게임 (BigSmall 등 8개) → `null` 반환
- 존재하지 않는 게임명 → `null` 반환

### jsonData.test.ts
- 5개 JSON 파일 구조 검증:
  - `levels` 배열 존재
  - 각 level에 `level`(number), `problems`(array) 존재
  - problems 비어있지 않음
- **wordwindow.json 특별 검증**: `answer` 값이 0~3 범위 (1-based 버그 수정 확인)
- **multiplicationboard.json 특별 검증**: `product === multiplicand × multiplier` 전수 검증 (96개 문제)

### useShellParams.test.ts
- `?level=5&from=shell&levelID=...&day=2&gameIndex=0`
  - `shellLevel === 5`
  - `isFromShell === true`
- `from=shell` 없을 때 `isFromShell === false`
- `level` 없을 때 `shellLevel === undefined`

### assetPath.test.ts
- `VITE_ASSET_BASE` 미설정 시 경로 그대로 반환
- 베이스 URL 설정 시 올바르게 결합

## TDD 원칙 적용 방법

새 기능 추가 시 아래 순서로 작업:

### 1. 테스트 먼저 작성 (Red)
```ts
// 예: 새 게임 JSON 추가 시
it('새게임 JSON이 올바른 구조를 가진다', () => {
  const data = newgameJson
  expect(data.levels).toBeDefined()
  expect(data.levels.length).toBeGreaterThan(0)
})
```

### 2. 코드 작성 (Green)
```bash
# 테스트 실패 확인
npm run test:run
# → FAIL (Red)

# JSON/Engine/Page 코드 작성
# → 테스트 통과 확인
npm run test:run
# → PASS (Green)
```

### 3. 리팩토링 (Refactor)
- 테스트 통과 상태 유지하면서 코드 정리
